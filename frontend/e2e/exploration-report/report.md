## Bug 汇总

### 🔴 Bug #1 [MAJOR] 音乐播放器 Mini Bar 遮挡点击区域

- **页面:** /play (游戏主界面)
- **严重程度:** Major
- **分类:** Bug

**描述:** 游戏页面底部的迷你音乐播放器 (`bg-card/95 backdrop-blur-sm border-t`) 的可点击区域延伸到了内容区上方，拦截了所有指向其后面元素（包括故事选择按钮）的点击事件。Playwright 自动重试了500+次点击，每次都被 `intercepts pointer events` 拦截。

**期望:** 音乐播放器只响应自己可见区域内的点击，不遮挡故事选择按钮

**实际:** `<div class="relative bg-card/95 backdrop-blur-sm border-t md:border md:rounded-b-lg flex items-center gap-2 px-3 py-2 cursor-pointer">` 和 `<div class="min-h-screen flex flex-col bg-background">` 交替拦截指针事件

**重现步骤:**
1. 注册并创建角色，开始游戏
2. 等待 AI 生成故事内容和选择项
3. 尝试点击选择按钮（如"直奔望江楼，查探真相"）
4. 点击被音乐播放器遮挡，无法触发

**建议修复:** 检查 mini player 容器的 `pointer-events` 和 z-index 层级，确保只有可见的播放器区域响应点击，不遮挡上方的内容区域。

### 🟡 Bug #4 [MINOR] 选择按钮文本分散在子元素中

- **页面:** /play (游戏主界面)
- **严重程度:** Minor
- **分类:** Bug/A11y

**描述:** 故事选择按钮的文本分散在多个子元素中。例如：
```html
<button>
  <generic>"1"</generic>
  <generic>直奔望江楼，查探真相</generic>
  <img>
</button>
```
虽然按钮的 accessible name 正确（"1 直奔望江楼，查探真相"），但 `textContent()` 在某些情况下返回空字符串，导致自动化工具和潜在辅助技术难以识别按钮。

**期望:** 按钮文本应直接可访问，`textContent()` 应返回有意义的文本

## 故事内容质量

AI 生成的故事质量令人印象深刻：

- **字数:** 约1500字完整章节
- **风格:** 章回体古典小说（"第一回 寒雾锁江寻旧迹，孤舟破浪问前程"）
- **时代:** 南宋端平元年（1234年），临安府
- **叙事手法:** 
  - 说书人视角（"看官听说"、"欲知后事如何，且听下回分解"）
  - 环境描写细腻（雾、江、庙）
  - 对话生动（船夫与主角互动）
  - 悬念设置恰当（神秘符号、纸条、尸体）
- **选择设计:** 3个有意义的剧情分支（直奔望江楼/先打听底细/折返再搜线索）
