# 首日与后续章节的检查核对（2026-09-28）

首日需要介绍人物，但不应因此多一套拒稿标准。本次将每日模式 v2 的首日专用写法检查全部改为非阻断提示；同一质量档、同一事实和必需人物条件下，首日与后续章节使用相同的硬性验收标准。不同日期拥有的已知事实和必需登场人物仍可能不同。

## 逐项决定

| 检查 | 合理性与处理 |
| --- | --- |
| 首段出现主角姓名 | 姓名稍后出现或先用代词并不意味着人物身份错误。改为提示；实际人物身份冲突仍由共同校验处理。 |
| 首段命中人生愿景文字 | 子串命中不能证明语义正确，未命中也不能证明背离目标。改为提示，允许换词表达和后文引出。 |
| 首段恰好一句 | 写作偏好，已是提示，保留。 |
| 首段命中冲突词 | “却、但”等不是冲突存在的充分必要条件，已是提示，保留。 |
| 不使用开场套话 | 文学质量建议，不影响选项或存档，改为提示。 |
| 至少两段 | 首日没有额外要求段落数量的理由，改为提示；共同正文结构检查继续执行。 |
| 第二段命中场景词 | 地点和动作可以出现在任意段落，已是提示，保留。 |
| 空正文、正文标题 | 每日模式所有日期均检查，不另加首日门槛。日期由界面展示，标题限制属于共同呈现约定。标题启发式仍可能误判，不能称为语义完备。 |
| 正文篇幅、碎片化、重复 | 继续使用共同策略及质量档配置；不按首日额外加码。当前软篇幅开关允许长度建议不阻断交付。 |
| 人物、时代、日期、当前年龄、已知事实与一致性 | 首日与后续共有，防止改名、穿越、违背已保存事实；不以“首段没有姓名”代替身份判断。规则/模型均有误判边界。 |
| 结尾命中决策关键词 | 所有章节均为 LOW、零权重；未命中不会单独要求重写。实际选项仍独立校验。 |
| 选项、事件标识、保存、按用户读取 | 所有章节必须满足可玩性与数据完整性要求，继续保留。 |

首日提示词仍鼓励介绍人物与目标、尽早建立场景，但全部标为 SHOULD。移除了“首段必须写出目标”的定点重写反馈。普通生成、已有正文恢复和预定事件统一调用 `split_daily_opening_issues`。七个首日提示保留独立日志规则码，不能因这些提示触发重写、熔断或安全开场。

首日安全开场属于失败后的恢复措施，继续保留；它不是额外的正文验收规则。后续章节有旧故事可保留，两者恢复行为仍不同。发布 smoke 仍会拒绝把安全开场冒充真实模型正文通过，但不再硬性要求首日正文至少两段。

## 同时修复的年龄误判

- `date_info.age` 只属于主角，旧实现却拿它比较账本中所有人物的年龄。现在只对账本明确标识的主角比较；不把 NPC 初始年龄当作当前权威年龄。
- 去掉姓名后任意六个字符的宽泛匹配，仅匹配直接年龄陈述，避免“林见微的母亲六十岁”归到林见微。
- 假设、否定、传闻、未来年龄和回忆不作为确定性当前年龄冲突。仍继续扫描后文；“假如……？林见微现在三十岁”中的真实错误会被识别。
- 这是保守的确定性检查，不是完整的自然语言理解；代词归属、含蓄叙述及复杂时态仍有能力边界，共同的语义一致性检查仍执行。

## 回归覆盖

- 中英文，同一正文放在第 1、2、31 天，硬性检查结果一致；空正文、明确标题仍被拦截。
- 三个质量档的单段开头、延后姓名/目标，正文只生成一次、原文交付并可恢复。
- 预定事件在首日/后续均接受上述写法，保留必需登场人物条件。
- 真实生产编排、文件 SQLite、按用户 HTTP 读取、选择结算到第二天；供应商响应使用固定夹具。
- 保留真实硬错误引发的重试、熔断、预算耗尽及安全开场回归，避免测试继续依赖已经软化的风格检查。
- NPC、亲属年龄、假设/否定、回忆后真实错龄、正确年龄后再次写错等双向用例。

真实模型验证记录另见 `first-day-real-provider-reproduction-2026-09-27.md`。通过有限样本不能证明未来不存在误判；本次保证的是消除已核对的首日额外拒稿门槛，而不是模型或检查器永不失败。
