# 收藏实体识别与入库修复计划

## 目标

修复每日时间线下人物、物品、标志物识别与收藏为空或串类的问题，并保证历史数据可以通过受控迁移恢复。重点覆盖孙悟空题材中的金箍棒、花果山等强语义实体，同时保留通用故事的识别能力。

## 实施步骤

1. 先补回归测试，固定以下行为：
   - 收藏识别优先读取 `day_history`，兼容旧的 `round_history`，并避免当前事件重复加入。
   - 强语义物品和地点不能被识别为人物；人物名后跟常见叙事动词的截断片段不能入库。
   - 每日后处理得到的实体会写入 `PlayerState` 的三类收藏，重复处理不会重复新增。
   - 收藏 API 追加实体时再次执行类型边界校验。
   - 前端首次打开收藏不会自动把识别结果全部写入。

2. 实现统一历史适配器，供收藏 API 与每日识别共用，按 `day_history`、`round_history` 的优先级读取并规范化事件字段。

3. 加强实体类型校验与确定性补充：
   - 集中维护强语义物品、标志物词表与跨类别排除规则。
   - 扩展物品、标志物的确定性提取，避免完全依赖当前事件中的 LLM 返回。
   - 在识别输出和收藏写入两层过滤错误的人物候选。

4. 将每日后处理的识别结果接入收藏物化流程，保证结果随当前状态保存，并以已有名称实现幂等。

5. 关闭前端首次加载时的自动全量添加，保留用户主动识别与选择添加的流程。

6. 增加只读预览、显式 `--apply` 的历史收藏迁移工具：移除已知错误人物，按完整历史补回确定性物品和标志物；不在本次本地验证中直接修改线上数据库。

7. 运行针对性测试、前端静态检查和完整后端单测，核对 worktree diff，最后报告代码验证与线上迁移的边界。

## 验收标准

- 新增回归测试全部通过。
- 原有后端单测无新增失败。
- 每日实体识别不再只看单个当前事件，且每日结果会进入三类收藏。
- `金箍棒`、`花果山` 等实体不会进入人物列表。
- 历史迁移默认只预览，只有显式 `--apply` 才会写数据库。
