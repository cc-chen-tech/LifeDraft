# 同一主角的三张候选形象

## 目标与边界

角色创建时，用户能从同一个主角的三张形象中选择。姓名、年龄、性别、身世、性格、故事起点和时代设定对三张图相同；脸型、发型及服装搭配有可辨认的差异，服饰与道具符合故事所处时代及文化。图片在进入人物形象步骤前开始后台生成。已选图片在刷新、重新登录和后续场景生成中保持一致。

本次只改变主角 `player_main` 的候选形象流程。其他人物、地点、物品的生成不变；旧游戏已有的一张形象继续可用，不自动产生额外的付费生成请求。

## 当前流程与依赖

现有 `generate_character_images(num_images=3)` 先生成主图，再以它为参考生成变体，提示词还要求外貌不变，因此不能直接用于三种长相。`StepPortrait` 已有多图缩略图；`useImageStore` 只在内存里保存序号，重新加载时选回第一张。图像服务的场景参考回退到 `is_primary`。异步人物形象任务在 PR #382 中实现，约一分钟以上的生成由后台执行，浏览器轮询任务状态；本功能以该分支为依赖，合并和发布仍分别进行。

## 生成与任务模型

游戏创建成功后，客户端发起一次“三张候选”入队请求，立即拿到批次任务 ID。服务端从游戏的已确认角色设定取一份固定快照，记录故事起点修订号。相同游戏、相同修订号的重复入队返回进行中的批次，不重复收费生成。返回响应丢失时，客户端按游戏查询现有批次并继续轮询。

批次有三个固定槽位。每个槽位独立调用一次单图文生图，不把第一张作为其余两张的参考，也不复用一个要求固定容貌的外貌锚点。三个提示词共用角色事实、画风、时代和文化约束，各自给出不同的外貌与衣着方向；不改写人物身世和性格。提示词、快照版本、批次及槽位编号随图片保存，便于追查。当前已有的时代约束继续应用于每个槽位。自动生成的内容不能靠单元测试保证视觉差异或史实准确，需用真实模型做人工验收。

扩展持久任务为一个批次任务，并保存每个槽位的进度及图片 ID。每张成功后立即持久化并展示；三个槽位互不依赖。任务中断后对照已保存的槽位恢复，只补未完成的槽位。单个槽位失败时，已完成图片继续可选，界面显示“已完成 n/3”与失败槽位的重试入口。重试只补失败或缺失槽位。故事起点修订号改变时，旧批次不得激活图片或覆盖当前选择；新修订号需要新的批次。服务端控制同一游戏的并发批次，避免重复点击造成重叠的付费请求。

## 保存与选择

候选批次和三个槽位持久保存。另以游戏 ID 保存唯一的 `selected_image_id`，不把“生成时的第一张”这个 `is_primary` 含义改造成选择标记。服务端的选择接口校验用户拥有游戏、图片属于该游戏的主角、位于可选批次且文件可用，之后原子更新选择。接口返回服务器确认的选中图片 ID；客户端按图片 ID 显示选中态，刷新后从服务端恢复，不依赖数组顺序。

首张候选完成时，如该游戏还没有选择，则将它设为暂用形象；用户点选其他候选后以用户选择为准，后续候选完成不抢回选择。开场图和后续场景生成在未显式传入图片 ID 时读取持久选择；显式传入时仍校验图片属于当前游戏且有效。旧游戏没有选择记录时，回退到现有有效主图，并在用户选图时写入选择记录。

## 两种重新生成

“根据修改意见重新生成”只处理当前选中的一张，沿用以该图为参考的编辑流程；其他候选保留。后台生成期间旧图仍可用。新图完成并通过批次及故事起点版本校验后，原子替换原槽位；如果原图仍是所选图，同时把持久选择切到新图。失败或任务作废时保留旧图和原选择。

“完全重新生成”创建新的三个独立候选槽位。旧批次及当前选中形象在新图生成时继续可用；新候选逐张展示，用户选中新图后才切换持久选择和生效批次。新批次部分失败时可选择已完成图片，并只补失败槽位；如果始终没有新图成功，旧批次保持生效。按钮文案应说明会生成一组三张新形象，以及大约发生三次图片生成。所有重新生成请求继续采用立即返回任务 ID 加轮询的方式，浏览器请求不等待图片提供方返回。

## 界面与兼容性

人物形象步骤显示已完成数量、三张候选和每张的生成状态；点击候选后等待服务端确认，再更新选中标记。若新批次还在生成，旧选中形象仍标为“当前使用”。刷新、断线、重新登录时恢复批次、槽位和选择，轮询中断只显示可恢复状态，不把生成中任务误报为失败。仅有一张图的旧游戏维持现有操作，点击“完全重新生成”时再进入三候选流程。

## 验收与测试

1. 服务端测试断言三次独立文生图调用、不同的外貌及服装方向、共同的角色事实和时代约束，并断言无首图参考；不得仅断言返回三张。
2. 任务测试覆盖入队立即返回、重复入队、丢失响应恢复、每槽持久化、进程重启补缺、单槽失败重试、旧起点任务作废，以及同游戏并发冲突。
3. 选择测试覆盖归属校验、无效或跨游戏图片拒绝、刷新后恢复、首次暂用图不覆盖用户选择、场景参考和开场图使用选中图。
4. 重新生成测试覆盖只替换目标槽位、失败保留旧图、完成时仅在原图仍被选中时更新选择；全新一组不提前覆盖旧选择。
5. 浏览器端到端测试用受控慢提供方或任务桩模拟超过 60 秒、请求连接断开、页面刷新及部分槽位失败，验证进度恢复和没有重复生成。普通 CI 不调用付费提供方。
6. 上线前另做一次受控真实提供方验收，人工检查三张脸和服装有区别、同一主角设定一致、符合时代，并核对每张可持久读取；将该结果与自动测试、合并、部署状态分别报告。
